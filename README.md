# منصة الأستاذ محمد أبوشاكر لعبودي — دليل الإعداد

## 1) ما الذي يعمل الآن بدون أي إعداد؟
افتح `index.html` مباشرة في المتصفح (أو انشره كما هو) وستعمل هذه الأجزاء فورًا بلا حاجة لأي إعداد:
- كل الدروس المتوفرة (14 درسًا من أصل 16، بانتظار درسي التوكيد والنعت)
- الخريطة الذهنية والفيديو ونص كل درس
- **اختبار الفهم** لكل درس (يعمل محليًا بالكامل، بلا إنترنت حتى)
- **إعراب الجمل** (101 جملة + الاختبار الشامل الثاني) بالتعرف على الصوت
- التصميم الكامل + إمكانية التثبيت على الهاتف/الحاسوب

## 2) ما الذي يحتاج ربطًا بـ Firebase؟
- تسجيل التلاميذ (الاسم واللقب) والموافقة عليهم
- الجلسة الواحدة لكل تلميذ
- فتح/إغلاق الدروس والفصول من لوحة التحكم
- الترتيب (لتمارين الدرس مستقبلاً)
- لوحة تحكم الأستاذ/المشرف (طلبات الانتظار، الإحصائيات)

### خطوات الربط:
1. افتح مشروعك في https://console.firebase.google.com
2. من ⚙️ إعدادات المشروع → أضف تطبيق ويب → انسخ كائن `firebaseConfig`
3. افتح ملف **`firebase-config.js`** والصق القيم مكان `"ضع_...هنا"`
4. من القائمة الجانبية فعّل **Firestore Database** فقط (وضع الإنتاج) — لا حاجة لـ Storage ولا لأي طريقة Authentication
5. غيّر **`window.ADMIN_PIN`** في نفس الملف إلى رقمك السري الخاص (4 إلى 8 أرقام)

### قواعد أمان Firestore المقترحة (الصقها في تبويب Rules):
🔴 **مهم جدًا إن كان مشروعك منشورًا مسبقًا:** إن كنت قد نسخت هذه القواعد إلى Firebase Console
من قبل، فإن تعديل هذا الملف وحده لا يغيّر شيئًا — القواعد الفعلية تبقى القديمة حتى تعيد
نسخ القواعد الكاملة أدناه وتلصقها في تبويب **Rules** بمشروعك على
https://console.firebase.google.com ثم تضغط **نشر (Publish)**. تحديدًا، السطر الجديد
`allow delete: if true;` ضروري لعمل زر "حذف تلميذ" في لوحة التحكم — بدونه يرفض Firestore
أي محاولة حذف برسالة خطأ صلاحيات (permission-denied).
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /students/{id} {
      allow read: if true;
      allow create: if true;
      allow update: if true; // يفضّل لاحقًا تقييدها عبر Cloud Functions لمزيد من الأمان
      allow delete: if true; // ⚠️ ضرورية لزر "حذف تلميذ" في لوحة التحكم — بدونها يفشل الحذف برسالة خطأ صلاحيات (permission-denied)
    }
    match /state/{doc} {
      allow read: if true;
      allow write: if true; // محمي عمليًا بالرقم السري داخل التطبيق فقط، وليس قاعدة بيانات حقيقية
    }
    match /notifications/{id} {
      allow read: if true;
      allow write: if true; // محمي عمليًا بالرقم السري داخل التطبيق فقط، وليس قاعدة بيانات حقيقية
    }
    match /submissions/{lessonId}/students/{studentId} {
      allow read: if true;
      allow create: if true;
      allow update: if false; // يمنع تعديل نتيجة بعد إرسالها (محاولة واحدة فقط)
    }
  }
}
```
🔴 **مهم جدًا:** إن ظهرت مشكلة "جرس الإشعارات لا يضيء" أو "رسالة الأستاذ لا تصل للتلاميذ" أو
"الدرس يبقى يظهر مقفلاً رغم فتحه"، فالسبب في الغالب هو عدم وجود قاعدة `match /notifications/{id}`
بالضبط كما هي أعلاه (أو نسخة قديمة من القواعد بها `allow write: if request.auth != null...`
لمجموعتي `state` أو `notifications` — هذا التطبيق **لا يستخدم Firebase Authentication إطلاقًا**،
فأي قاعدة تشترط `request.auth` ستمنع كل كتابة من الأستاذ بصمت). تأكد من نسخ القواعد الكاملة
أعلاه بالضبط إلى Firebase Console ← Firestore Database ← Rules ← نشر (Publish).
⚠️ ملاحظة أمنية: نظام الرقم السري الحالي بسيط (مضمّن في كود الواجهة الأمامية)، وهو كافٍ
كخط دفاع أول بحسب طلبك، لكنه ليس حماية عسكرية — لا تشارك رابط لوحة التحكم أو الرقم السري
علنًا. لتشديد الأمان لاحقًا يمكن الانتقال لـ Firebase Authentication حقيقي + Cloud Functions.

## 3) رفع التطبيق على GitHub Pages
1. أنشئ مستودعًا جديدًا على GitHub وارفع كل ملفات مجلد `app/` كما هي.
2. من إعدادات المستودع → Pages → فعّل النشر من الفرع الرئيسي (Branch: main، المجلد: /root).
3. سيصبح رابط تطبيقك: `https://اسم_حسابك.github.io/اسم_المستودع/`
4. أي تعديل تريده لاحقًا (فتح/إغلاق درس لا يحتاج هذا، فهو من لوحة التحكم مباشرة) —
   لكن **إضافة محتوى جديد** (تمارين الدرس، دروس جديدة كالتوكيد والنعت) تتم بتعديل الملفات
   المذكورة أدناه ورفعها مباشرة عبر واجهة GitHub، دون لمس بقية الكود.

## 4) كيف تضيف درسًا جديدًا (مثل التوكيد أو النعت)؟
افتح ملف **`lessons-data.js`**، ابحث عن الكائن الذي فيه `locked:'pending'` لنفس الدرس
(مثلاً `id:'tawkid'`)، واستبدله بكائن كامل بنفس بنية الدروس الأخرى الموجودة فوقه
(title, subtitle, def, video, tree, mcq) ثم احذف السطر `locked:'pending'`. احفظ وارفع
الملف على GitHub — سيظهر الدرس تلقائيًا في التطبيق (يبقى مقفلاً حتى تفتحه من لوحة التحكم).

## 5) كيف تضيف "تمارين الدرس" أو "الفروض والاختبارات"؟
هذا الإصدار جاهز من ناحية الواجهة (قسم "تمارين الدرس" وتبويبات الفصول موجودة وتعمل)،
لكنه يعرض حاليًا رسالة "قريبًا" لأن آلية القراءة التلقائية لملفات `content/exercises/`
و `content/exams/` لم تُفعَّل بعد بشكل كامل (وضعنا فقط البنية والتوثيق داخل `content/README.md`
تمهيدًا لها). تواصل معي لإكمال هذا الجزء بمجرد أن ترسل أول نموذج فعلي لتمارين درس واحد،
حتى تُصمَّم آلية القراءة والتصحيح بدقة على مثاله.

## 6) قائمة الملفات
| الملف | الوظيفة |
|---|---|
| `index.html` | هيكل الصفحات كلها |
| `style.css` | كامل التصميم |
| `app.js` | كل المنطق: Firebase، التسجيل، القفل، الاختبارات، لوحة التحكم |
| `lessons-data.js` | محتوى الدروس (عدّل هنا لإضافة/تعديل درس) |
| `irab-data.js` | محتوى تبويب إعراب الجمل |
| `firebase-config.js` | مفاتيح مشروعك + الرقم السري (عدّل هنا فقط) |
| `manifest.json` + `sw.js` | إعدادات التثبيت (PWA) |
| `teacher-avatar.jpg` / `teacher-watermark.jpg` | صورك — استبدلها بصور أعلى جودة إن توفرت |
| `content/` | مكان تمارين الدرس والفروض المستقبلية |
